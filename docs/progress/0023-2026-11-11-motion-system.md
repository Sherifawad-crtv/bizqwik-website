# 0023 — Motion system (phase 1 of the landing rebuild)

**Date:** 2026-11-11 · Direction: replicate the reference landing page's motion design and unify it across the site so anything new reuses it.
Plan and phases: `docs/PLAN-landing-outline.md`. Spec: `docs/MOTION.md`.

## What changed
- **Measured the reference** (CSS, JS bundles, frame-by-frame video of load and scroll). Findings and numbers in `docs/MOTION.md` section 1.
- **Tokens** (`src/motion/tokens.ts`, rewritten): three named bezier eases from the reference (`standard`, `enter`, `spring`), a duration ladder (0.1 to 0.75, plus count and spin), staggers, `gap.beat`, entrance offset, press scale, view start lines. Eases are registered with GSAP `CustomEase` in `motion/gsap.ts`. CSS twins added to `styles/tokens.css`.
- **Kit** (`src/motion/primitives.ts`): `enter`, `revealOnView` (`data-reveal` attribute, mounted once by `<Motion />` in the layout), `playOnView` + `replay`, `swapIn`, `pressFeedback`, `scrubWords`. New `ReplayButton` component.
- **Migrated everything that moves:**
  - Ecosystem demos: all eases and durations are tokens. Demos now **play once** when scrolled to and hold their finished frame (they used to loop forever); tab switch plays the new demo; a Replay pill restarts it. Removed the heading word-by-word entrance and the card rise: headings are static, the stage enters through `data-reveal`.
  - Navbar and mobile sheet: tokens (sheet enters with the shared entrance).
  - Hero and navbar scroll timelines: eases come from `ease.scrub.*` (same curves as before, so the tuned feel is unchanged); the hero's time-based intro uses tokens.
  - Hover and press in CSS: `duration-(--dur-*) ease-standard`, press `scale-95` (Button, navbar, chips).
- **Guard:** `npm run check:motion` verifies CSS twins equal the TS tokens and fails on raw ease strings, raw numeric tween durations and Tailwind `duration-NNN` outside `src/motion/`. Scrub files are exempt from the duration rule (documented).
- **`/foundation` "Motion" section:** every ease, the duration ladder (Play), `data-reveal`, `pressFeedback`, `scrubWords`, so the system is reviewable in a browser.
- **Plan:** `docs/PLAN-landing-outline.md` (8 phases, the 6-section outline, open decisions).

## Bugs found and fixed while testing
- `replay()` must rewind before re-measuring. `invalidate()` on its own left the previous end state on screen until each tween began, so the Replay button looked inert.
- Reveals were firing at page load because they were created before the hero's pin spacer existed. They are now set up two frames after mount.

## Verification (Chromium, production build)
- Payout demo: plays once (violet idle, spinner, green Paid), holds for 9s, Replay returns to the idle frame and plays again; tab switch plays the new demo. Reveal wrapper is hidden before scroll and entering on scroll. `/foundation`: reveal stagger, ladder play, word-by-word dimming, no console errors.
- Hero (scatter, headline, phone), navbar and mobile menu render as before. `tsc`, `oxlint`, `check:content`, `check:motion`, `next build` pass.
