# 0034 — CTA corner radius: 20px, 100px on hover

**Date:** 2026-11-11 · Direction: make CTAs 20px and 100px on hover, smoothly, CTAs only.

## What changed
- `components/ui/Button.tsx` (the one component behind every CTA: hero, navbar, mobile menu, closing cards): `rounded-[20px]` at rest, `hover:rounded-[100px]`, with `border-radius` added to the transition list
  (`duration.fast` 0.25s, `ease.standard`). Hover only applies on devices that can hover (Tailwind v4 default), so touch screens keep the 20px corners.
- Not changed, as asked: the Replay pill (14px), the navbar menu button (18px), link pill and logo tile, the skip link, and the `--radius-button` token (24px, still used by the skip link and the /foundation demo button).
- `docs/DESIGN-SYSTEM.md` states the CTA rule.

## Verification (Chromium, production build)
- Computed radius of the hero button: 20px at rest, 48 / 83 / 95 / 100px sampled every 45ms after hover (smooth ease, done in about 0.25s), 100px settled, back to 20px after leaving. Secondary hero button and the navbar CTA read 20px at rest; Replay still 14px. No console errors.
  `tsc`, `oxlint`, `check:motion`, `next build` pass.

## Notes
- At 56px tall, anything from 28px up is already a full pill, so the 100px target looks identical to 28px; the larger value only changes how long the curve takes to settle.
