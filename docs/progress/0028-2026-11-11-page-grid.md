# 0028 — Page grid from the reference; all sections share one width

**Date:** 2026-11-11 · Direction: inspect the reference's screen width of grid, apply it on desktop, make every section the same width.

## Measured (reference, 390 to 2560px wide)
Content max-width **1672px**, centred. Side gutter **64px** above 1024px, **24px** from 641 to 1024, **12px** up to 640. Cards 16px apart.
Their header, dark box and cards share one left edge and width at every size (for example 1440: x 64, width 1312; 1920: x 124, width 1672; 2560: x 444, width 1672).

## What was wrong
We had a 1280px container with 16/32px gutters, and several sections set their own wrappers (the closing section nested two paddings, the feature stage and the
statement section used their own `max-w-page` and `px-*`). At 1440 our content was 1216px wide; theirs is 1312px, and at 1920 it was 1280 against 1672.

## What changed
- `--container-page` is now 1672px; new `--gutter` (12 / 24 / 64px) and a `page-width` Tailwind utility (`max-width: container + 2 gutters`, padding = gutter), in `globals.css`.
- One wrapper everywhere: `Container` (now `page-width`) in the statement section, benefits, feature stage, the Plans / Add-ons / FAQ shells and the closing section; the navbar header uses the same gutter and max width;
  the `/foundation` page too. The closing section no longer nests padding.
- Card gaps are 16px (benefits, closing cards, the feature stage's two panels). The feature chip row's phone bleed uses the gutter.
- Documented in `docs/DESIGN-SYSTEM.md` ("Page grid") with the rule: no section wrapper sets its own `max-w-*` or `px-*`.

## Verification (Chromium, production build)
- Left edge and width of the navbar bar, statement box, benefits grid, feature stage (layout width), Plans, Add-ons, FAQ and closing box measured at 390, 768, 1024, 1100, 1280, 1440, 1920 and 2560px:
  identical in every section at every width, and equal to the reference's numbers (12/366, 24/720, 24/976, 64/972, 64/1152, 64/1312, 124/1672, 444/1672). No horizontal overflow, no console errors.
  (The feature stage reads 5% narrower in a bounding-box measurement until it has scrolled in, because its entrance starts at 95% scale; its layout width is the same.)
- `tsc`, `oxlint`, `check:content`, `check:motion`, `next build` pass.
