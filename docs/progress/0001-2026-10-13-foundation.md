# 0001 — Foundation: scaffold, fonts, tokens

**Date:** 2026-10-13 · **Stage:** design foundation (no page sections yet)

## What changed
- Scaffolded Next.js 16 (App Router) + TypeScript + Tailwind v4, npm, oxlint.
- **Fonts, self-hosted** in `src/assets/fonts/` (Latin subset, SIL OFL licences
  alongside): Urbanist variable (100–900; we use 500–800) and Space Mono 400/700.
  Wired through `next/font/local` in `src/app/fonts.ts`, `display: swap`.
- **Tokens** in `src/styles/tokens.css` (Tailwind `@theme`): colours, status/tag
  colours, radii, shadows, fluid type scale, layout widths, breakpoints, and the
  brief's default motion values. Source: app repo `src/index.css` "Foundation
  tokens", cross-checked with brief §3.2–3.4. Values match exactly.
- **Base styles** in `src/styles/globals.css`: Paper background, Ink text,
  3px violet focus ring, squircle corners via `[data-sq]`, reduced-motion
  reset, `overflow-x: clip`, `scroll-padding-top` for the sticky nav.
- **Brand assets** in `public/brand/` (`wordmark.png`, `mark.png`) and
  favicons + `apple-touch-icon.png` at `public/` root, copied from the app repo.
- `/foundation`: a living style guide that renders every token. `/` redirects
  to it for now (temporary, removed when the real page exists). The site is
  `noindex` until launch.
- Docs: this log, `DESIGN-SYSTEM.md`, `DECISIONS.md`, `ROADMAP.md`.

## Why
Lock the visual primitives once, in one place, so the design direction work
only changes values and layout, never hunts for hard-coded colours. The brief
and the app repo agree on every token, so the website and the product look
like one system.
